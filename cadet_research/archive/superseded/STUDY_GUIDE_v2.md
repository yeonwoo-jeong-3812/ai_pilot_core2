## 4. 시뮬레이션은 어떻게 생겼나

**5계층 구조** (위에서 아래로 명령이 내려간다)

| 계층 | 주기 | 하는 일 |
|---|---|---|
| 전술(행동트리, BT) | 20 Hz | "추격하라", "회피하라", "사격하라" 같은 행동을 고른다 |
| 기본 전투 기동(BFM) 유도 | 60 Hz | 행동을 "기수를 이만큼 돌려라"(각속도 명령)로 바꾼다 |
| G·받음각 리미터 | — | 명령이 기체 한계(+9 G/−4 G, 받음각 25°)를 넘지 않게 자른다 |
| **INDI 각속도 제어기** | 120 Hz | 각속도 명령을 따라가도록 조종면(승강타·에일러론)을 움직인다. **고장은 여기에만 넣는다** |
| JSBSim F-16 | 120 Hz | 비행 물리 |

**INDI 제어 법칙** (증분 비선형 동적 역변환)

| 식 | 쉬운 뜻 |
|---|---|
| ν = K(ω_cmd − ω_f) | 명령 각속도와 실제(필터 거친) 각속도의 차이에 비례해 "이만큼 가속하자"를 정한다 |
| Δu = G⁻¹(ν − ω̇_f) | 원하는 가속과 지금 가속의 차이를 조종면 효과 G로 나눠, 조종면을 얼마나 **더** 움직일지 정한다 |
| u = u_f + Δu | 지금 조종면 위치에 증분을 더한다(그래서 "증분") |

- 피치·롤만 INDI가 맡는다. F-16 모델 안의 원래 비행제어 법칙(FLCS)은 피치·롤에서 우회했다(겹치면 G가 4.5–7.2 G에 묶였다). 요 축만 FLCS가 맡는다.
- 기준값: K = 9 s⁻¹, 동기화 필터 25 Hz(2차), 120 Hz.

**두 제어기 구성**

| | 원래 (본실험·대부분의 실험) | 실제형 (P7–P9) |
|---|---|---|
| 구동기 | 속도 제한만(전 행정 0.3 s) | 반응 지연(1차, 20.2 rad/s ≈ 0.05 s) + 속도 제한(승강타 60 °/s, 에일러론 80 °/s) |
| 각가속도 | 시뮬레이터 정답값 | 자이로 각속도를 미분(차분)해서 구함 |
| 측정 지연을 견디는 정도 | 약 1틱(8.3 ms)부터 스스로 떨기 시작(한계 순환) | 5틱까지 안정 |
| 안정 여유 | — | 이득 여유 16.4 dB, 위상 여유 59.3° (표준 6 dB·45° 만족 → 게인 재조정 없음) |
| 만든 방법 | 키트 그대로 | 엔진 파일을 고치지 않고 실행 중에 감쌈(`kit/supplementary/p7_realistic.py`) |

## 10. 예상 질문과 답 (발표·심사 대비)

| 질문 | 답 |
|---|---|
| 0.053과 0.022 중 무엇이 맞나? | 둘 다 각자의 구성에서 맞다. 비례 상수는 구성마다 다시 맞춰야 하고, 우리 주장은 "양의 관계"와 "오차 유형 효과"다 |
| D는 성능이 아니지 않나? | 맞다. D는 결과가 기준에서 얼마나 흔들렸나다. 방향은 한 기체 고장 실험으로 따로 봤다 |

| 둔한 오차 효과는 κ의 특성 아닌가? | 아니다. 명령 전달 지연과 낮은 k_q에서도 확인했다(+0.330). 다만 0.4 s 명령 지연은 주로 지면 충돌 경로였다 |
| 고장 난 비행기가 점수가 오르는 게 말이 되나? | 원래 제어기의 자체 진동이 위치 관계를 바꿔 공세 시간이 15배가 된 결과다. 실제형 구성에서는 반등이 없고 고장이 클수록 손해였다 |
| 왜 둔한 오차가 더 해롭나? | 교전 명령은 느린 신호다(0.14 Hz). 자세 오차 ≈ 각속도 오차 ÷ 각주파수이므로 느린 오차는 기수 방향을 크게 바꾸고 빠른 떨림은 평균이 0으로 돌아온다(해석) |
| 시뮬레이션만으로 실기에 적용할 수 있나? | 아니다. "이 시뮬레이터, 이 제어기 구조에서"로 한정한다 |
| 사후 분석이 많지 않나? | 결과를 본 뒤의 질문은 실행 전에 기준을 고정한 새 실험·새 시드로 확인했고, 분석마다 등록 여부를 공개했다 |
| 재현은 같은 조건을 다시 돌린 것 아닌가? | 맞다. "시드에 따른 우연을 배제했다"까지만 주장한다. 새 원인으로의 일반화는 E3·E3X·P8이 답한다 |
