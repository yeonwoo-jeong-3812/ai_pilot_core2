## 1. 한 쪽 요약 — 이 연구가 묻는 것

### 1.1 질문

> 교전 중에 **"명령한 피치 회전과 실제 피치 회전의 차이"** 하나만 재면,
> 제어기가 왜 나빠졌든 상관없이 **승패가 얼마나 달라질지 예측할 수 있는가.**

### 1.2 왜 중요한가

제어기를 바꿀 때마다 공중전을 **수천 번** 돌려야 승패 영향을 안다. 교전은 작은 차이도 키우는
**혼돈계(chaotic system)** — 같은 조건에서도 결과가 흩어져서, 평균을 보려면 반복이 많이 필요하다.
**[해설추가]** 비유하면 당구공을 똑같이 쳐도 매번 다른 데로 가는 것과 같다. 그래서 한 번으로는
못 보고 수백 번을 쳐서 분포를 봐야 한다.

이 연구는 **더 싼 방법**을 찾는다. 교전을 몇 번만 돌려 추종 오차를 재고, 그 값으로 "승패가 몇 %나
달라질지"를 **곡선으로 환산**하는 것이다.

### 1.3 비유 (운전대)

| 비유 | 이 연구 |
|---|---|
| 운전대를 돌리는 것 | 피치 각속도 **명령** (상위 유도 계층이 INDI에 주는 값) |
| 차가 실제로 도는 것 | 피치 각속도 **응답** (JSBSim이 계산한 실제 값) |
| 빗나간 정도 | **mae** = 명령과 응답 차이의 절댓값 평균 [°/s] |
| 레이스 성적이 달라진 정도 | **D** = 기준 대비 결과가 달라진 경기의 비율 |
| 나빠지는 원인 | 필터, 지연, 모델 오차, 게인, 잡음 (여섯 가지) |

**핵심**: 원인이 무엇이든 **빗나간 정도만 재서** 성적 변화를 맞히려는 것이다.

## 2. 제어 구조 — 무엇을 제어하고 있나

### 2.1 5계층 스택 **[코드 근거]** `kit/aircombat/engine/pilot.py`

| 계층 | 주기 | 하는 일 | 쉬운 말 |
|---|---|---|---|
| L1 전술 행동트리 (BT) | 20 Hz | 추격 유형, G 사용 수준, 조준점 선택 | "뭘 할지 정한다" |
| L2 BFM 유도 | 60 Hz | 교범 기반 G 조절, 리프트벡터 배치, 추력 | "어느 방향으로 얼마나 당길지 정한다" |
| L3 제어 | 120 Hz | 자세 shim → 리미터 → **INDI 각속도 제어기** | "그걸 조종간 입력으로 바꾼다" |
| L4 비행역학 | 120 Hz | JSBSim F-16 (내장 FLCS 포함) | "기체가 실제로 움직인다" |
| L5 기록 | — | 읽기 전용 기록 | "무슨 일이 있었는지 적는다" |

**[해설추가]** 이 연구가 건드리는 것은 **L3의 INDI 한 군데뿐**이다. L1 전술과 L2 유도는 고정이다.
그래서 "같은 전술인데 제어기만 달라지면 어떻게 되는가"를 물을 수 있다.

**중요**: INDI의 출력은 조종면 각도가 아니라 **F-16 내장 FLCS에 주는 조종간 명령**
(`fcs/aileron-cmd-norm` 등, −1~+1)이다. 즉 이 연구의 INDI는 **FLCS가 이미 붙은 기체**를 제어한다.
**논문 Ⅲ-B에 반드시 쓸 것** — 조종면을 직접 명령하는 구조와 결과가 다를 수 있다는 한계의 근거다.

### 2.2 INDI가 무엇인가

**INDI** (Incremental Nonlinear Dynamic Inversion, 증분 비선형 동적 역변환).

**[해설추가]** 일반 제어기는 "지금 상태에서 목표까지 가려면 조종면을 얼마나 움직여야 하나"를
**기체 모델로 계산**한다. 모델이 틀리면 틀린 만큼 어긋난다.

INDI는 다르게 한다. **"지금 각가속도를 측정하고, 거기서 얼마나 더 가야 하는지만 계산"**한다.
현재 상태를 측정으로 알기 때문에 모델 의존이 적다. 이것이 INDI가 "모델 오차에 강하다"고 하는 이유다.

제어 법칙 **[코드 근거]** `kit/aircombat/control/indi.py`

```
ν  = k_rate · (ω_sp − ω_f)          ... 목표 각가속도 (오차에 비례)
Δu = G⁻¹ · (ν − α_f)                ... 조종 입력을 얼마나 더 움직일지
u  = u_f + Δu                        ... 새 조종 입력 = 이전 값 + 증분
```

| 기호 | 뜻 | 쉬운 말 |
|---|---|---|
| ω_sp | 각속도 명령 [rad/s] | "이만큼 돌아라" |
| ω_f | 필터를 통과한 측정 각속도 | "지금 이만큼 돌고 있다" |
| α_f | 필터를 통과한 측정 각가속도 | "지금 이만큼 빨라지고 있다" |
| u_f | 필터를 통과한 이전 조종 입력 | "지금 조종간이 이만큼 들어가 있다" |
| k_rate | 각속도 게인 (기준 9, 9, 6) | "오차에 얼마나 세게 반응할지" |
| G | 제어 효과 행렬 | "조종간 1만큼 넣으면 각가속도가 얼마나 생기나" |
| 아래첨자 f | 2차 Butterworth **동기화 필터** 통과 | 아래 설명 |

### 2.3 동기화 필터가 왜 핵심인가

**[코드 근거]** `indi.py`에서 `f_acc`, `f_act`, `f_rate` 세 필터가 **같은 차단주파수 f_c**로 만들어진다.

**[해설추가]** INDI는 "현재 각가속도"와 "현재 조종 입력"을 **빼서** 증분을 구한다. 두 값의 시각이
어긋나면 뺄셈이 틀린다. 그래서 **같은 필터를 세 신호에 똑같이 걸어 위상(시간 지연)을 맞춘다.**
이것이 "동기화(synchronization)"의 뜻이다.

- 차단주파수를 **낮추면**: 잡음이 잘 걸러지지만 **느려진다** (위상 지연 증가)
- 차단주파수를 **높이면**: 빠르지만 **잡음이 그대로 들어온다**

기준값은 **25 Hz**다. 이 연구는 25, 12, 5 Hz 세 가지를 쓴다.

## 3. 열화 원인 여섯 가지 — 무엇을 어떻게 망가뜨리나

**[코드 근거]** `kit/run.py:apply_knobs`. 전부 **실행 중에 INDI 객체를 감싸서** 주입한다.
엔진 코드 자체는 고치지 않는다.

| 원인 | 코드 키 | 주입 방식 | 쉬운 말 | 본실험 수준 |
|---|---|---|---|---|
| **제어효과 모델 오차** | `kappa` | `indi.G0[1,:] *= κ` — INDI가 믿는 피치 제어 효과를 κ배로 | "조종간이 실제보다 κ배 잘 듣는다고 착각" | 2, 4, 8, 16, 25, 50 |
| **피치 게인** | `kq` | `indi.k_rate[1] *= kq` | "오차에 얼마나 세게 반응할지" | 0.25, 0.5, 1.5, 2 |
| **동기화 필터** | `filt_hz` | 세 필터를 같은 새 f_c로 재생성 | "얼마나 부드럽게 거를지" | 25, 12, 5 Hz |
| **자이로 잡음** | `sigma_dps` | 측정 각속도에 백색잡음 더함 | "센서가 떨린다" | 0.3, 1, 3, 6 °/s |
| **비동기 지연** | `delay_async` | 측정만 N틱 늦게 읽음 | "센서만 늦다" | 0~6틱 (0.5틱 단위) |
| **동기 지연** | `delay_sync` | 측정과 조종 입력 되먹임을 **함께** N틱 늦춤 | "센서와 조종간 되먹임이 같이 늦다" | 2, 4, 8, 16틱 |

1틱 = 1/120 s ≈ **8.33 ms**.

**비동기와 동기의 차이 [해설추가]**: INDI는 "현재 각가속도 − 현재 조종 입력"을 쓴다.
- **동기**: 둘 다 똑같이 늦으면 뺄셈 자체는 맞다. 다만 전체가 과거 정보다.
- **비동기**: 측정만 늦으면 **뺄셈의 두 항이 서로 다른 시각**이 된다. 증분 계산이 틀어진다.

이것이 비동기 지연이 훨씬 치명적인 이유이고, 이 연구가 곡선을 맞출 때 **비동기 지연을 쓴 이유**다
(큰 추종 오차를 만들 수 있어서).

**소수 틱 처리 [코드 근거]**: `delay_async`가 0.5 같은 소수면 이웃 두 틱 값을 선형 보간한다.
이것으로 0.5틱 간격의 촘촘한 용량-반응 곡선을 만들 수 있다.

## 4. 두 지표 — mae와 D

**논문 Ⅳ-B의 핵심이다. 이 절을 이해하지 못하면 논문을 못 쓴다.**

### 4.1 mae — 예측 변수

**[코드 근거]** `kit/run.py:apply_knobs`의 `st["ae"] += abs(x - y)`,
여기서 `x = 피치 각속도 명령 [°/s]`, `y = 실제 피치 각속도 [°/s]`.
경기가 끝나면 틱 수로 나눠 평균을 낸다. 양 기체(`blue_mae_q_dps`, `red_mae_q_dps`) 평균이 그 경기의 mae.

```
mae = (1/N) Σ |피치 명령 − 피치 응답|      [°/s]
```

| mae 값 | 뜻 |
|---|---|
| 0.2 °/s | 기준 제어기. 거의 명령대로 따라간다 |
| 2–3 °/s | 눈에 띄게 어긋난다 |
| 7–10 °/s | 심하게 어긋난다 |

**[해설추가]** 왜 **절댓값 평균(MAE)**이고 제곱평균(RMSE)이 아닌가 — 코드에 설명이 없다.
**[해설추가]** MAE는 큰 오차에 덜 민감해서 몇 번의 큰 튐이 전체를 지배하지 않는다.

### 4.2 D — 결과 변수 (주)

**[코드 근거]** `kit/predict.py:per_seed`. 같은 (대진, 시나리오, 시드)에서 기준 조건(BASE) 경기와
비교해, **승자(`winner`)나 종료 사유(`condition`)가 다른 경기의 비율**.

```
D = (결과가 달라진 경기 수) / (전체 경기 수)
```

종료 사유 5종: `health_zero`(격추), `hard_deck`(저고도 이탈 패), `timeout`(시간 종료 후 HP 비교),
`no_contact`(무접촉), `stall`(실속).

**왜 승자만 안 보고 종료 사유까지 보나 [해설추가]**: 같은 쪽이 이겼어도 **격추로 이기던 것이
시간 종료 승으로 바뀌면** 교전 양상이 달라진 것이다. 승자만 보면 이걸 놓친다.
이것은 기존 계보에서 "승패의 73–82 %가 지면 충돌"이라고 지적한 문제를 **정의 단계에서 해결**한 것이다.

### ⚠ D가 재는 것은 "성과 저하"가 아니다 (2026-10-19 검토 결과)

열화는 **양 기체에 대칭으로** 걸린다 (`RESEARCH_PLAN.md` §5.2).
전원 총당 리그에서 대칭으로 걸면 **총 승수가 구조적으로 거의 고정된다.**

| 조건 | 승 | 패 |
|---|---|---|
| BASE | 1307 | 1375 |
| F5_D6 (가장 심한 열화) | 1313 | 1373 |

**[해설추가]** 모두가 똑같이 못해지면 **누가 이기는 순서만 섞이고 총 승수는 그대로**다.
그래서 D는 **"결과가 얼마나 재배열됐나"**를 재지 **"성과가 얼마나 나빠졌나"**를 재지 않는다.

**논문에서 "성과 변화"라고 쓰면 안 된다.** "결과 불안정성" 또는 "결과 재배열"로 쓴다.

**D의 범위와 포화 [코드 근거]** `report_E2.md` §4: 무상관 기준이 **0.597**이다.
**[해설추가]** 이 값은 "변형 경기의 결과를 기준 분포에서 무작위로 뽑았다면 기대되는 불일치율"이다.
D가 0.6에 가까우면 **개별 경기가 사실상 새로 뽑은 것과 같다**는 뜻이고, 그 위는 구별이 안 된다.
**논문 한계에 반드시 쓸 것.**

### 4.3 M — 결과 변수 (보조)

참가자별 리그 점수 변화 절댓값의 평균 [점/리그 한 바퀴]. 점수는 **승 3, 무 1, 무접촉 0**.

### 4.4 순환 논리 반론과 답 (논문 Ⅳ-B)

**반론**: mae와 D가 **같은 교전에서** 나온다. 그러면 "자기 자신으로 자기를 예측"하는 것 아닌가.

**답 [코드 근거]**:
- **mae는 그 조건 교전의 제어 품질**이다. 기준 경기와 비교하지 않는다.
- **D는 그 조건 교전과 기준 교전의 결과 비교**다. 두 경기가 필요하다.

정의가 겹치지 않는다. mae는 한 경기 안의 양, D는 두 경기 사이의 양이다.
**이 문단을 Ⅳ-B에 반드시 넣는다** (`REVIEW_LOG.md` ISS-04).

## 5. 실험 네 개 — 무엇을 왜 나눴나

### 5.1 설계의 핵심: 적합 집합과 검증 집합의 분리

| 실험 | 조건 | 쓰임 |
|---|---|---|
| **E2 (적합)** | 필터 × 비동기 지연 **20조건** | 이 데이터로만 곡선을 맞춘다 |
| **E3 (검증)** | κ, k_q, 잡음, 동기 지연, 조합 **22조건** | E2 곡선으로 **미리 예측**하고 실제와 비교 |

**[해설추가]** 같은 데이터로 곡선을 맞추고 그 곡선이 그 데이터를 잘 맞힌다고 말하면 당연한 소리다.
**곡선을 맞출 때 보지 못한 조건**을 맞혀야 의미가 있다. 이것을 **표본 밖 예측**이라 한다.

**중요한 단서**: E2와 E3는 **같은 시드**(`main-*`)를 쓴다. 즉 "표본 밖"은 **시드가 아니라 조건 기준**이다.
초기 조건이 같아야 짝 비교로 잡음을 줄일 수 있기 때문이다.
**논문 Ⅳ-C에 이 점을 명시한다** (`REVIEW_LOG.md` ISS-02).

### 5.2 시드 분리 — 데이터를 섞으면 안 되는 이유

| 시드 접두어 | 실험 | 쓰임 |
|---|---|---|
| `feas*` | 사전 실험 | **주제와 가설을 세운 탐색 데이터. 판정에 쓰지 않는다** |
| `cal-*` 8개 | E1 | **허용폭 δ를 정하는 데만** 쓴다 |
| `main-*` 8개 | E2, E3 | 곡선을 맞추고 예측을 검증한다 |
| `gen-*` 4개 | E4 | 일반화 |
| `smoke-*` | 실행 점검 | 결과로 쓰지 않는다 |

**[해설추가]** 왜 이렇게 나누나 — 기준(δ)을 정한 데이터로 판정까지 하면, 기준을 결과에 맞춰
고른 셈이 된다. 그래서 δ는 `cal-*`로만 정하고 판정은 `main-*`에서만 한다.
이 원칙은 기존 계보의 개정 A35 §5에서 온 것이다.

### 5.3 네 실험의 역할

| 실험 | 규모 | 답하는 질문 | 실패하면 |
|---|---|---|---|
| **E0 자가점검** | 13경기 | 장치가 제대로 도나 | 다른 실험을 하지 않는다 |
| **E1 보정** | 2,688경기 | 잡음 바닥은 얼마인가 | δ가 실용 바닥보다 크면 그대로 쓰고 보고 |
| **E2 적합** | 28,224경기 | mae와 D의 관계는 어떤 모양인가 (RQ1) | 단조 관계가 없으면 RQ2·RQ3를 안 한다 |
| **E3 검증** | 30,912경기 | 원인이 달라도 같은 곡선인가 (RQ2) | 실패한 원인이 "추종 오차 밖의 경로"라는 결과 |

**실패해도 결과가 되게 설계되어 있다.** 이것이 좋은 사전등록 설계의 특징이다.

**[해설추가] 왜 등록된 판정은 통과했나** — 판정 규칙이 **"원인별 평균 예측 오차가 ±δ 안"**이라
**수준만 보고 기울기를 안 본다.** 그리고 δ = 0.079가 검증 구간 신호 폭(D 0.100–0.301)의

**논문에서는 "전 원인 예측 성공"이 아니라 "수준은 예측하지만 기울기는 원인에 따라 다르다"로 쓴다.**
자세한 근거와 요청 작업은 `docs/FEEDBACK_FOR_CADET_v1.md` §2.1에 있다.

## 7. 통계 — 어떻게 판정하나

### 7.1 독립 단위는 시드

**[해설추가]** 경기 하나하나는 독립이 아니다. 같은 시드 안의 경기들은 같은 초기 조건에서 나왔고,
같은 참가자들이 여러 번 만난다. 그래서 **리그 한 바퀴(= 시드 하나)를 한 표본**으로 센다.
E1–E3는 시드 8개, E4는 4개다.

### 7.2 시드 부트스트랩

**[해설추가]** 시드 8개를 **중복 허용으로 8개 다시 뽑는 것**을 2,000번 반복한다.
그때마다 **곡선을 다시 맞추고 다시 예측**한다. 그 2,000개 예측 오차의 2.5 %~97.5 % 구간이 95 % CI다.

**중요**: 곡선을 **표본마다 다시 맞춘다**. 곡선을 한 번 고정하고 예측 오차만 흔들면
곡선의 불확실성이 CI에 안 들어간다.

### 7.3 3구간 판정 **[코드 근거]** `kit/predict.py:judge`

| 조건 | 판정 |
|---|---|
| CI가 [−δ, +δ] 안에 완전히 들어감 | **예측 성공** |
| CI가 δ를 완전히 벗어남 | **예측 실패** |
| 그 밖 | **판정 불가** |

**[해설추가]** "유의하지 않다"와 "차이가 없다"는 다르다. 전자는 "못 봤다"일 수도 있다.
δ를 미리 정하고 CI가 그 안에 들어가야 **"없다"고 적극 선언**할 수 있다.
이 틀은 기존 계보(개정 A24 §9, A31 §5, A35 §5)에서 온 것이다.

## 8. 논문 쓸 때 반드시 지킬 것

### 8.1 쓰면 안 되는 문장

| 쓰면 안 되는 말 | 왜 | 대신 쓸 말 |
|---|---|---|
| "추종 오차가 승패를 결정한다" | D는 승패가 아니라 **결과가 달라진 비율**이다 | "결과 변화율을 예측한다" |
| "추종 오차로 제어기 성능을 평가할 수 있다" | 이 연구는 **변화량 예측**이지 성능 평가가 아니다 | "제어기 변경의 교전 영향을 가늠할 수 있다" |
| "사전 실험에서 ~했다"를 결과로 | `feas*` 데이터는 **판정에 쓰지 않는다** | 사전 실험은 §FEASIBILITY에만 |
| "D = 0.6이면 성과가 절반 나빠진다" | D 0.6은 **무상관 기준**이라 포화 구간이다 | "D는 약 0.6에서 포화된다" |
| "모든 원인에서 예측이 성공했다"만 쓰고 끝 | 개별 조건에는 큰 오차가 있다 | 묶음 평균과 개별 조건을 함께 보고 |

### 8.2 반드시 써야 하는 한계 (현재까지 확인된 것)

1. **D의 포화** — 약 0.6에서 포화. 무상관 기준이 0.597이라 그 위는 구별이 안 된다
2. **절편 0.144** — mae가 0이어도 D 0.144를 예측한다. SHAM(실제 0.013)을 맞히지 못한다 (E4)
3. **E2와 E3가 같은 시드** — "표본 밖"은 조건 기준이지 시드 기준이 아니다
4. **E4는 판정 없음** — 참가자가 달라 부트스트랩 짝이 없다
5. **적합 범위 밖 외삽 금지** — 사전 실험에서 동기 24틱(mae 9.85)을 외삽했다가 0.35 빗나갔다
6. **상대가 행동트리뿐** — 학습 정책(RL)으로 일반화할 수 없다
7. **시뮬레이션만** — INDI가 내장 FLCS를 거치는 구조다. 실기 일반화 불가
8. **곡선 모양 선택** — 사전 실험 데이터로 모양을 고르면 순환이라, E2에서 LOO로 다시 골라 등록했다
   (`REVIEW_LOG.md` ISS-03)
9. **⚠ 원인별 기울기가 다르다** — 등록된 판정은 수준만 보고 기울기를 안 본다. κ 0.203 대 k_q 0.016 (§6.3)
10. **⚠ D는 결과 재배열이지 성과 저하가 아니다** — 대칭 열화라 총 승수가 고정된다 (§4.2)
11. **⚠ E3 수준이 사전 실험보다 좁다** — 실패가 드러난 조건(κ 100·400, 동기 24틱)이 빠졌다.
    검증 mae 최대가 9.85 → 3.55로 줄었다
12. **⚠ 적합 20조건 중 8개가 무상관 구간(D > 0.403) 위에 있다** — 기울기의 절반을
    "개별 경기 수준에서 무정보"인 점들이 정한다
13. **⚠ 시드 8개 퍼센타일 부트스트랩은 과소 커버리지** — CI가 좁아질수록 "성공" 판정이 쉬워진다

## 9. 용어집

| 용어 | 영문 | 뜻 |
|---|---|---|
| **INDI** | Incremental Nonlinear Dynamic Inversion | 측정한 각가속도를 써서 "얼마나 더 움직일지"만 계산하는 제어 기법 |
| **동기화 필터** | synchronization filter | 각속도·각가속도·조종 입력에 같은 저역통과 필터를 걸어 시각을 맞추는 것 |
| **차단주파수** | cutoff frequency, f_c | 필터가 걸러내기 시작하는 주파수 [Hz]. 낮을수록 부드럽고 느리다 |
| **제어효과 행렬** | control effectiveness matrix, G | 조종 입력 1단위가 만드는 각가속도 |
| **κ (kappa)** | — | G_model / G_true. 제어기가 믿는 효과와 실제의 비 |
| **비동기 지연** | asynchronous delay | 측정만 늦는 것. 증분 계산의 두 항이 다른 시각이 된다 |
| **동기 지연** | synchronous delay | 측정과 조종 입력 되먹임이 함께 늦는 것 |
| **틱** | tick | 1/120 s ≈ 8.33 ms. 제어 한 스텝 |
| **mae** | mean absolute error | 피치 명령과 응답 차이의 절댓값 평균 [°/s] |
| **D** | — | 기준 대비 승자나 종료 사유가 달라진 경기의 비율 |
| **M** | — | 참가자별 리그 점수 변화 절댓값 평균 [점/바퀴] |
| **SHAM** | sham condition | κ = 1 + 10⁻⁶. 물리적으로 구별 불가능한 가짜 변형. 잡음 바닥 측정용 |
| **δ (delta)** | tolerance | 허용폭. 이보다 작은 차이는 "없다"고 본다 |
| **대리 지표** | surrogate | 재기 어려운 양 대신 재는 싸고 쉬운 양 |
| **표본 밖 예측** | out-of-sample prediction | 모형을 맞출 때 보지 못한 데이터를 예측하는 것 |
| **LOO** | leave-one-out | 하나씩 빼고 맞춰 그 하나를 예측하는 검증법 |
| **시드 부트스트랩** | seed bootstrap | 시드를 중복 허용으로 다시 뽑아 불확실성을 재는 방법 |
| **대응 설계** | paired design | 같은 조건에서 설정만 바꿔 짝지어 비교하는 설계 |
| **Kendall τ** | Kendall's tau | 두 순위가 얼마나 같은지 재는 상관계수 (+1 = 완전 일치) |
| **혼돈계** | chaotic system | 작은 차이가 시간이 지나며 크게 벌어지는 계 |
| **FLCS** | Flight Control System | F-16 내장 비행제어계. INDI는 이 위에서 조종간 명령을 준다 |
| **BFM** | Basic Fighter Maneuvers | 기본 전투기동. L2 유도 계층이 구현 |
| **WEZ** | Weapon Engagement Zone | 무기 교전 영역. 기수 30° 원뿔, 500–3,000 ft |
| **hard_deck** | — | 저고도 한계(1,000 ft) 이탈. 즉시 패 |
