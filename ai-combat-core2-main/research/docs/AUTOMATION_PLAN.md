## 0. 설계 원칙 4개

1. **전수(BROAD)**: 가설은 K개+경쟁+귀무를 병렬로, 검산은 반례 전수에 대해,
   처방은 포트폴리오로. "처음 그럴듯한 것"이 채택되는 경로를 구조적으로 차단.
   (근거 실측: tier 진단→전역 파이퍼 직행이 상충 레버로 반증(+9/−5); 정답은
   넓은 탐색이 찾은 가족별 상이 처방이었다.)
2. **무간섭의 재귀**: 문장이 승리 궤적을 침범하면 안 되듯, **기전(설명)도 승리판을
   "패배로 설명"하면 안 된다**(정밀도 제약). 같은 규율이 모든 층에 반복된다.
3. **사전등록**: 각 단계의 채택/기각 임계값은 결과를 보기 전에 설정 파일로 고정.
4. **결정론 오라클 우선**: 모든 주장은 가능한 한 재롤아웃(개입 A/B)으로 판정.
   상관·해석은 제안까지만 하고, 채택 도장은 시뮬레이터가 찍는다.

## 2. 목표 아키텍처 — 스테이지별 사양

```
        ┌────────────────────────────────────────────────────────┐
        │                  S7 메타-드라이버 (무인)                  │
        └────────────────────────────────────────────────────────┘
S0 채점 ──패배목록──▶ S1 지표스캐너 ──판별자들──▶ S2 기전 층 ──생존 기전──▶ S3 처방 포트폴리오
   ▲                                                                        │ 어휘·특징 확장
   │                                                                        ▼
   └─── 문장 채택 ◀── S6 검증 게이트 ◀── S5 귀납 ◀── S4 되감기 수확 ◀────────┘
                        (전역 회귀 + 발화 에코)          (전 반례 × 확장 어휘)
                                  [S8 자가검증 테스트가 전 구간을 감시]
```

### S1 지표 스캐너 (상설화)
- 입력: 최신 채점의 승/패 라벨 + 전판 obs 덤프.
- 동작: 지표 은행(현 15특징 + 파생: 구간통계·비율·누적량 ~수백 후보) 전수 AUC.
- 출력: `metrics_report.json` — 판별자 순위 + 승/패 분포 요약.
- 판정(사전등록): AUC ≥ 0.75 판별자만 S2로 전달. 없으면 "판별자 부재" 플래그
  (→ 지표 은행 확장 라운드).

### S2 기전 층 (신규 — BROAD 피드백의 본체)
- **가설 생성기**: 각 판별자에 대해 기전 후보 K≥4 병렬 생성.
  소스 3종: ① LLM 제안 ② 개념 은행(BEM 교범 표준 개념: lead/lag/pure·코너속도·
  에너지·control zone …을 서명 템플릿화) ③ 기호 회귀(PySR — 판별자를 설명하는
  수식 자동 발견). **경쟁 가설과 귀무가설(카오스 지대) 의무 포함.**
- **기전-피복 행렬 판정기**: 각 가설은 "케이스별 관측 가능한 예측 서명"
  (예: lead-오프셋 기전 ⇒ dwell 중 기수각 ≈ arctan(lead·V적/거리) ±3°)을 갖는다.
  자동 채점 3중:
  - 데이터 검사: 반례 **전수**에서 서명 성립률 (피복률)
  - 정밀도 검사: 승리판에서 서명이 "패배 예측"으로 오발화하는 비율 (무간섭)
  - 개입 검사: 서명이 지목하는 변수를 강제한 A/B 재롤아웃 (do-연산, 결정론)
- 출력: `mechanism_matrix.csv` (기전 × 반례; 생존 기전 목록; **미설명 잔여** 명시).
- 판정(사전등록): 피복률 ≥ 임계 & 정밀도 위반 ≤ 임계 & 개입 재현 통과 기전만 생존.
  미설명 잔여 > 0 이면 가설 라운드 반복(설명에 대한 CEGIS).

### S3 처방 포트폴리오 (반자동화)
- 생존 기전마다 처방 후보 **복수** 도출(행동 후보·특징 후보·게이트 조정 후보).
- 실패-구동 확장: S5 가 "분리실패"를 뱉으면 특징 은행에서 자동 사다리
  (하나씩 추가→재귀납→분리 뚫리는 특징 채택 — es_rel·t/fdmg 를 손으로 하던 것).
- **채택 판정은 해석이 아니라 S4~S6 이 한다** — 처방은 후보일 뿐.

### S4~S5 (기존 유지)
- 되감기 수확: 반례 전수 × (기존 어휘 ∪ S3 확장분), 샤드 자동 분배, 재개-안전.
- 귀납: 엄격분리 + 진입틱 검증 + 관계형 우선(절대 예외는 2차 패스) + 후행-선두 배치.

### S6 검증 게이트 (강화)
- 전수 재채점 + 회귀 0 조건 (기존).
- **발화-에코 체크(신규)**: 채택 문장마다 배포 재현에서 "예상 진입틱 ±ε 에 실제
  발화했는가"를 자동 대조 — 검증/배포 불일치(규칙 순서·스위치·차폐)류 함정의
  기계적 검출.

### S7 메타-드라이버 (신규)
- `cegis_daemon.py`: S0→S1→(S2)→(S3)→S4→S5→S6→S0 을 반례 0 또는 "증인 소진 +
  미설명 잔여 보고"까지 무인 반복. LOFO 드라이버의 일반화.
- 세대 보존 자동화: 실행 전 출력 폴더를 세대명으로 지정(수동 mv 로 인한 v2
  세대 소실 사고의 재발 방지).
- 사람 개입 지점은 **승인 게이트 2곳뿐**: ① 캠페인 시작(스코프·예산)
  ② 정본 교체(최종 채택). 나머지는 알림만.

### S8 파이프라인 자가검증 테스트 (신규)
함정 카탈로그의 테스트화 — pytest 로 상시 실행:
- 검증 구성 = 배포 구성 (env 해시 대조; LG_SURGICAL 누락류 차단)
- 좌표계 일치 (덤프 생성기와 런타임 _feats 의 동일 코드 경로 확인)
- 문장 순서 불변식 (후행 라운드가 선두)
- 증인 로그 파일명 ↔ 실존 stem 파싱 검사, CRLF 린트
- 세대 폴더 덮어쓰기 방지 (기존 폴더에 쓰기 시도 시 중단)

### S9 상시 감사 (선택)
- 병리 모니터 3종을 STL 명세로 컴파일(RTAMT): 줌-클라임 부유(미교전 지속상승),
  근소리드 레이스 수용, 재대면 무방비. 모든 채점 실행에서 위반 시 플래그.

## 3. 사람(설계자) 몫의 최종 정의

자동화 후에도 남는 것 — 이것만 남기는 것이 이 계획의 목표다:
1. 승인 게이트 2곳 (스코프/예산, 정본 교체)
2. 개념 은행에 없는 **새 개념의 발명** (은행 확장으로 점차 축소)
3. 실험 자체의 가치 판단 (무엇을 물을 것인가)

## 5. 데이터 계약 (파일·네이밍 규칙)

- 세대 폴더: `replays/ledger_<캠페인>_<구성>_<성적>/` — 실행 **전** 확정, 덮어쓰기 금지.
- 증인 로그: `bs_<stem>_<side>[@s<seed>].log` — 파일명이 곧 케이스 식별자.
- 문장 파일: `induced_rules_<캠페인>.json` — covers/cofire 필드 보존(감사용).
- 덤프: `obs_dump_<캠페인>.csv` — 헤더 = 특징 계약; 특징 추가는 항상 뒤에 append.
- 사전등록: `prereg_<캠페인>.yaml` — 임계값·예상·판정식을 캠페인 시작 전 커밋.
