# L2 가이던스 계층 비교 — core-live vs core2 (★연구본체)

> 대상:
> - core2 `guidance/{bfm_guidance.py(294), doctrine.py(122)}` — 무상태 연속 BFM 조절법
> - core-live `control/guidance.py(1007)` — Tactic enum → setpoint 변환 라이브러리(25+ 기동)
> 방법: 제어 프리미티브·상태성·기동 표현·근거·설명가능성 5축 대조.

## 결론 먼저: **근본 아키텍처 분기 — "지능"을 어느 계층에 두는가**

이것이 두 프로젝트의 **가장 깊은 차이**다. 우열이라기보다 패러다임 분기다.

| | core2 | core-live |
|---|---|---|
| L2 성격 | **연속 조절법 1개**(`BFMGuidance.compute`) | **이산 기동 라이브러리 25+개**(`_gun_track`, `_smart_dive`, `_high_yoyo`…) |
| 지능의 위치 | **연속 L2 조절**(풍부) + 얇은 L1 모드플래그 | 얇은 L2 변환 + **이산 L1 전술선택**(42/42 cost-tree) |
| L2 출력 | **dphi(리프트벡터 배치)** + q_cmd + thrust → L3 직결 | **(psi\*, h\*, v\*) setpoint** → autopilot 추종 |
| 수직기동 | 조준점 수직오프셋(aim_above)→dphi (L3/L4 무변경) | 명시적 named tactic(SMART_DIVE/HIGH_YOYO/CLIMB) |
| 상태성 | **무상태**(매 tick 기하 재유도) | 대부분 무상태(일부 KF·scissors_state) |

**해석:** core2는 지능을 *연속 조절법*에 응축했다 — L1은 pursuit(pure/lead/lag)·mode(stable/control_zone)·max_g 플래그만 넘기고, 실제 BFM은 L2가 매 tick 연속 조절. core-live는 지능을 *이산 전술선택*에 응축했다 — L2는 25개 BFM 기동을 setpoint로 번역하는 라이브러리일 뿐이고, "무엇을 언제 할지"의 지능은 L1 cost-tree(일반해 루프1~16의 결정체)에 있다.

## 축 1: 제어 프리미티브 — dphi(리프트벡터) vs setpoint(heading/alt)

| | core2 | core-live |
|---|---|---|
| 프리미티브 | **dphi_cmd** = 리프트벡터를 조준점에 배치하는 롤 증분(body 프레임) | **psi_star/h_star** = 목표 heading·고도, 뱅크는 autopilot이 협조선회로 역산 |
| BFM 정합 | "리프트벡터를 밴딧에" — 실 BFM 조종 그대로 | 항법 setpoint 추종 — 한 단계 우회 |

**core2 우위(프리미티브):** dphi는 실제 조종사가 BFM을 수행하는 방식("put lift vector on bandit")을 직접 표현한다. body 프레임 증분이라 특이점 없음. core-live는 heading+altitude를 명령하고 autopilot이 뱅크를 역산 — 물리적으로는 동등하나 프리미티브가 한 단계 간접적이다.

## 축 2: 기동 표현 풍부도

| | core2 | core-live |
|---|---|---|
| 표현 방식 | 연속 조절 × {pursuit 3 × mode 3} + 수직오프셋 | **25+ named BFM 기동 함수** |
| 목록 | pure/lead/lag × regulate/stable/control_zone, aim_above 요요 | lead·pure·lag·vertical·adaptive·stern_convert·LDR·ETM·smart_dive·gun·one/two_circle·tight/lead_turn·scissors·high/low_yoyo·break·extension·climb… |
| 근거 | KAF 기본운용교범 F-16C Vol.5 (2005) Ch.4 | NAVAIR 00-80T-105·AFTTP 3-3.F-16·LAG |

**core-live 우위(풍부도):** 25개 명시 BFM 기동은 core2의 ~9 조합보다 표현력이 넓다. one-circle/two-circle, high/low yoyo, scissors, lag displacement roll, stern conversion 등을 *이름 붙은 이산 전술*로 갖는다 — cost-tree가 이들 중 argmax로 고를 수 있어 **설명가능한 전술선택**의 어휘가 된다. core2의 연속 조절은 우아하지만 "지금 high-yoyo 중"을 이산 라벨로 감사하기 어렵다(연속 regulation에서 창발).

## 축 3: 근거·감사가능성 — 교범인용 vs 실험튜닝

| | core2 | core-live |
|---|---|---|
| 상수 근거 | **전부 교범 인용**(corner 4.3.3.7, fighting 4.4.6.2.2, initial_pull 4.4.5.2…) | 실험 sweep·NME_* env override(SD_SPRINT, HIGH_G, ENERGY_FLOOR…) |
| 감사 | `Doctrine` dataclass + `DOCTRINE_BOUNDS`(교범대역) + 매 tick `audit` dict | replay·per-tick 계측(사후), 상수는 실험 유래 |
| 튜닝 개방 | 참가자 doctrine.yaml 대역검증(현재 미개방) | env override sweep(연구용) |

**core2 우위(감사):** 모든 setpoint가 교범 조항에 앵커돼 "감사가능 AI 전술"의 기준선을 이룬다 — `initial_pull_g=7.0 (4.4.5.2)`처럼 출처가 코드에 박혀 있다. `compute()`는 매 tick 12필드 audit dict(pursuit·g_mode·power_mode·in_slant_band…)를 반환. core-live 상수는 실험 유래(131.5947904706722 같은 sweep 산물)라 교범 근거가 약하고, 감사는 사후 replay 계측에 의존한다. **이 축은 core2가 명확히 우수** — 우리의 [[metrics-before-tactics]] 원칙과 부합하는 것은 오히려 core2다.

## 축 4: 조절 법칙 정교함 (core2 BFMGuidance 내부)

core2 `_regulate_g`는 5모드 연속 조절이다: `regulate`(ATA 비례 획득) → `track_lock`(LOS 회전율 추종 하한 G=V·ω/g, "획득≠추적" 갭 해소) → `initial_pull`(머지 6–8G) → `energy_backoff`(파이팅속도 미만 G 감쇠) → `max_g`(L1 트리거). `_power`는 6모드(AB_entry/closure_ctl/AB_accel/decel/margin_regain/MIL_hold). 이는 **연속 도메인에서 상당히 성숙한 BFM 법칙**이다 — 특히 `track_lock`의 "획득 법칙(ATA 비례)만으로는 근접 선회표적서 WEZ 원뿔 직전 평형에 갇힌다"는 진단은 정확하고, 우리 루프13의 closing-gate 문제와 같은 현상을 연속 조절로 푼다.

**주목:** core2의 `track_lock`(LOS 회전율 추종 G 하한)은 **우리 루프13 E1 무-전환의 closing-템포 게이트와 동일 문제를 다른 층에서 해결**한다([[loop13-e1-draw-converted-closing-gate]]). 우리는 이산 게이트(누적정체≥26s→VERTICAL_PURSUIT)로, core2는 연속 G 하한으로. → 상호 교차검증 가치 큼.

## 축 5: 검증된 결과

**core-live L2(+L1)만이 42/42 실증을 갖는다.** core2의 연속 조절법이 이론적으로 성숙해도, 실제 캐노니컬 17 + held-out 25에서 무패임이 증명된 것은 core-live 스택이다. core2 BFMGuidance가 몇 승 몇 무를 내는지는 **미측정**.

## 판정표

| 축 | 우위 | 근거 |
|---|---|---|
| 제어 프리미티브(리프트벡터 직접배치) | **core2** | dphi = 실 BFM 조종 표현, 무특이점 |
| 무상태·연속성(모드전환 불연속 없음) | **core2** | 매 tick 기하 재유도 |
| 근거·감사가능성(교범인용) | **core2** | 전 상수 KAF 교범 조항 앵커 + audit dict |
| 조절 법칙 성숙도 | **core2** | track_lock 등 5모드 G조절 |
| 기동 표현 풍부도 | **core-live** | 25 named BFM 전술 |
| 설명가능 이산 전술선택 어휘 | **core-live** | cost-tree argmax 대상 = 일반해 본체 |
| **검증된 전투 실증** | **core-live** | 42/42, both-INDI 300s |

## L2 총평

**L2는 core2가 가장 크게 투자한 계층(★연구본체)이고, 순수 제어·감사 품질로는 core2가 우수하다** — 리프트벡터 프리미티브, 무상태 연속 조절, 교범인용 setpoint, 성숙한 G/power 조절 법칙. 특히 **감사가능성(교범 앵커)은 core-live의 약점을 정확히 찌른다**: 우리 상수는 실험 sweep 산물이라 근거가 약하다.

그러나 두 프로젝트는 **지능의 위치가 다르다**. core-live는 지능을 *이산 L1 전술선택*(설명가능 cost-tree)에 두었고, 이것이 **대회 목표(설명가능 BT 기반 일반해)에 더 정합**하다 — 42/42 tick-identical .yaml은 "named 전술에 대한 읽을 수 있는 트리"라는 core-live 패러다임의 산물이다. core2의 연속 조절은 우아하나 "무엇을 왜 하는가"를 이산 BT로 감사하기는 상대적으로 어렵다(전술이 연속 조절에서 창발).

**흡수 후보(core-live로 역이식 가치 최상):**
1. **교범 앵커 doctrine.py** — 우리 실험상수를 교범 조항에 매핑해 감사가능성 확보([[metrics-before-tactics]] 원칙 강화). 최우선.
2. **dphi 리프트벡터 프리미티브** — setpoint(psi*/h*) 대신 리프트벡터 직접배치. L3 쿼터니언 shim과 함께 이식 시 수직 BFM 표현력↑.
3. **track_lock 연속 G 하한** — 우리 루프13 closing-gate와 교차검증. 연속-이산 두 해가 같은 무-전환 문제를 풀므로 상호 검증.

**검증 실험(후속):** core2 BFMGuidance+doctrine을 그대로 우리 하네스(canonical 17+held-out 25, both-INDI 300s)에 붙여 승/무/패를 실측 — "연속 교범조절 L2가 우리 이산전술 L2 대비 전투결과가 나은가"를 정량화. 이것만이 L2 우열의 확정법이며, 도크트린 반복결과([[ai-pilot-doctrine-optimizes-gun-wez-dwell]] "정교함≠승리")를 감안하면 결과는 예단 불가.
