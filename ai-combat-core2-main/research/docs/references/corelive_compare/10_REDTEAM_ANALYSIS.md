## 초록

core2는 두 역할을 겸한다 — **채점 플랫폼**이자 **대항군 파일럿**. 문제도 이 두 역할을 따라 두 축으로 갈린다.

- **축 A(플랫폼):** ~~채점 결함 7건~~ → **규칙 확정으로 대부분 해소.** 남는 것은 로컬 core2의 DPS 25→50 동기화 1건과 우리쪽 인프라·경미 항목(F3·F5·F6)뿐. core2는 이제 정의상 채점 정본이다.
- **축 B(대항군):** L2가 무상태 제어기라 **대칭 교착을 구조적으로 못 깬다** → 실력 있는 상대에게 무승부 → 대항군 실격. **이것이 남은 진짜 과제다.**

⚠️ **챔프 함의:** core-live의 42/42는 **다른 게임**(12° 선형·거리감쇠·25HP/s)의 해다. 확정 규칙은 더 관대하므로(30° 원뿔·거리무관·2× 격추속도) **승/무/패를 확정 규칙에서 재검증해야** 하며 42/42 유지를 가정할 수 없다.

# Part A — 계층 구조: core2 vs core-live

## A.1 두 엔진은 "같은 질문"을 다른 높이에서 자른다

매 순간 조종사는 "지금 뭘 하지?"에 답한다. 이건 5단으로 쪼개진다.

| 분해 | 예 |
|---|---|
| ① 역할/자세 | 공세·방어·중립 |
| ② 어떤 기동 | 하이요요·lag·연장 |
| ③ 얼마나 세게 | 몇 G, 어디로 기울일지 |
| ④ 어떤 조종면 | 스틱·러더 |
| ⑤ 물리 | 기체 실제 반응 |

```
            ①역할   ②기동      ③세기       ④조종면   ⑤물리
core-live:  └─ L1 ─┘(이름선택)  L2(레시피)   L3       L4
core2:      └─ L1 ─┘(거친의도)  └─── L2 ───┘(창발)    L3       L4
                             기동이 세기에서 창발
```

**한 문장 차이:** core-live는 "어떤 기동"을 **L1에서 이름으로 고르고**, core2는 "어떤 기동"이 **L2의 연속 조절(기울임·G)에서 저절로 만들어진다(창발).** L3·L4는 거의 같다.

## A.2 계층별 (자연어 / 코드 / 도그파이트)

**L4 물리 — 사실상 동일.** 둘 다 JSBSim, 폴백 함수 하나 빼고 바이트-동일. 코너속도·선회율·에너지 블리드·실속경계가 같다 → **기체 성능은 변수가 아니고, 위 계층(어떻게 조종하나)만 승부를 가른다.** 그래서 순수 BFM 지능 문제다.

**L3 제어 — "스틱·러더를 쥔 손".** 원하는 자세/각속도를 뒤집힘 없이 조종면으로 번역.
- core2 = INDI + 쿼터니언 + 결합 리미터(코너∩9G). **단일·특이점 없음** — 수직 기동 상단이 매끄럽다.
- core-live = LQR+INDI **이중 교차검증** + 이득여유 형식증명. "방금 안정했나" 감사 가능.
- 도그파이트: 둘 다 한계에서 코너를 잡는다. 제어공학 품질 백중, 표현만 다름(단순 vs 이중화·증명).

**L2 가이던스 — 여기서 아키텍처가 갈린다(핵심).**
- core2 L2 = **"BFM 두뇌"**: 추격유형만 받으면 매 틱 기울임·G·파워를 연속 생성. **기동에 이름이 없다** — 하나의 법칙이 모든 기동을 만든다. `compute(..., pursuit, max_g, aim_above, mode)`.
- core-live L2 = **"BFM 손"**: L1이 고른 이름을 받아 25개 명명 레시피(`_high_yoyo`, `_smart_dive` 등) 중 하나를 재생하는 디스패처.

> **같은 국면, 다른 내부표현** — *적이 위로 높게 교차, 그의 6시로 전환*:
> - core-live: L1이 **"하이요요"라는 이름 선택** → `_high_yoyo` 레시피. ("하이요요, 실행.")
> - core2: L1이 `pursuit=lead, aim_above_ft=750`만 설정 → L2가 조준점을 750ft 위로 올리고 기울임 → **요요 궤적이 창발.** `high_yoyo` 노드는 없다. ((무명) "리프트벡터 적 위로, 6.2G.")
>
> **비행경로는 대체로 같고, 차이는 설명 방식**: core-live는 "명명된 기동 타임라인"(참가자 설명가능성 정합), core2는 "매 틱 연속명령 감사로그"(부드러움·교범근거 정합).

**L1 전술 — "역할 선택 vs 기동 선택".**
- core2 L1 = **거친 의도**: "공세? lead냐 lag냐? 오프셋은?" 교범조건 BT. `tick→TacticCommand(pursuit, max_g, aim_above, mode)`.
- core-live L1 = **구체 결정**: 25기동의 게임값 argmax. `situation_cost.value(o)` + `suggest_tactic`.
- 핵심: **core2는 "어떤 기동"을 L1에서 안 정한다** — L2 창발. core-live는 L1의 이산 선택. 거친 붓질 vs 세밀한 붓질.

## A.3 구조 요약

| 계층 | core2 | core-live | 도그파이트 의미 |
|---|---|---|---|
| **L1** | 거친 의도(pursuit+mode) | 게임값 argmax(25 기동) | 역할선택 vs 기동선택 |
| **L2** | 연속 법칙(기동 창발) ★두뇌 | 25 레시피 디스패처 ★손 | 창발 vs 이름 |
| **L3** | INDI+쿼터니언(단일·특이점없음) | LQR+INDI 이중(교차검증·증명) | 스틱·러더 손 |
| **L4** | JSBSim | JSBSim(바이트-동일) | 같은 기체 |

**두 축의 대비:** ① 두뇌 높이 — core2=L2(연속), core-live=L1(이산). ② 표현 — core2=하나의 생성법칙(우아·감사로그), core-live=명명 레시피(직관·설명가능 타임라인). 둘 다 같은 물리·비슷한 제어 위에서 **"BFM 지능을 어디에 담느냐"만 다르다.**

## B.3 축 A — 채점 정확성 (2026-07-13 규칙 확정으로 대부분 해소)

**중대 정정:** 대회 공식 룰북(V2, 엔진=ai-combat-core2)이 확정됐다. 엔진 자체가 core2이므로 **core2의 채점 구현이 곧 정본**이다. 초판이 core-live의 RULEBOOK(각도 12° 선형 + 거리감쇠 + 25HP/s + 60Hz)을 정본으로 가정하고 잡았던 결함 중 3건이 무효화된다.

**확정 WEZ 규칙 (룰북 §4):** 데미지 = **50 HP/s × 각도계수**, 사거리 500–3000ft **균일**(거리계수 없음), <500·>3000ft = 0, 시간완화 없음. 각도계수 = ATA 계단: **<2°→1.0 / <10°→0.75 / <20°→0.5 / <30°→0.25 / ≥30°→0.**

| 초판 판정 | 확정 규칙 대조 → 결과 |
|---|---|
| **F1 🔴 WEZ 버그** | **해소.** 확정 규칙이 곧 core2의 30° 계단·거리균일. 단 **로컬 core2는 DPS 25→50 동기화 필요**(레포 최종본=50, 격추 4s→2s). |
| **F2 🔴 안전판정 누락** | **해소.** 룰북 §1·§5 = 참가자는 **BT(YAML)만 제출**, 비행제어층(리미터 포함)은 **전원 공통**. 과부하·스핀은 구조적으로 도달 불가 → 룰북이 의도적으로 규정 없음. core2 `match.py:27` 주석과 룰북 **정확히 일치.** (실속만 참가자 전술로 도달 가능 → 판정 있음, 정합.) |
| **F7 🟠 틱레이트** | **해소.** 룰북 §2 = 물리 120Hz · L1 tick 20Hz = core2 값. |

**남는 실질 항목 (전부 경미·우리쪽 인프라):**

| # | 항목 | 위치 | 성격 |
|---|---|---|---|
| **동기화** | 로컬 core2 DPS 25→50 (확정 규칙 반영) | `wez.py:11` | **유일한 채점 코드 변경** |
| **F3** | 리플레이 3종(ACMI+plot+CSV) | `match.py:69` | 우리 연구 워크플로 — core2 결함 아님 |
| **F5** | 실속 누적 부동소수 경계 | `match.py:106` | 경미(룰북 100kt/10s 자체는 정합, 수치위생) |
| **F6** | 단위상수 근사 | `bfm_guidance.py:35` | 경미 |
| **F4** | 평가배터리가 풀스택 파일럿인지 확인 | `tournament`/`scripted.py` | 확인 (룰북 §7.4 고정 배터리) |

**결론(축 A):** 규칙 확정으로 축 A는 사실상 닫혔다. core2는 정의상 채점 정본이며, 남은 건 로컬 DPS 동기화 1건 + 우리쪽 계측 인프라뿐이다. **"틀린 게임을 최적화한다"는 초판의 우려는 철회한다.**

⚠️ **단, 챔프 재검증은 반드시 남는다:** core-live 42/42는 12° 선형·거리감쇠·25HP/s 게임의 해다. 확정 규칙(30° 원뿔·거리무관·50HP/s)은 더 관대하므로 15~25° ATA 추적이 이제 25~12.5 HP/s를 준다. 승/무/패가 바뀔 수 있어 **확정 규칙에서 재측정 전엔 42/42를 가정하지 않는다.**

## B.4 축 B — 대항군으로서의 구조적 무승부

**원인:** core2 L2는 "기억 없는 조종사"다 — 눈앞 사진만 보고 반응하고 직전 수 초를 저장 안 한다. 총 조준·에너지 관리엔 정답이지만, **대칭 교착**에서 막힌다.

두 실력 기체가 대칭 배치(동속 2-서클, 덱 거울상, 나란한 평행)에 빠지면:
- 대칭 입력 → 대칭 출력. 양쪽 최선인데 **아무도 못 벗어난다.**
- 지금 사진은 좌우 대칭이라 **"이길 방향" 정보가 사진 안에 없다** → 300s 무승부.

이길 실마리는 "지금 사진"이 아니라 **"상대가 최근 뭘 해왔나"라는 이력**에 있다. 예: "위협받으면 도주, 아니면 재추격"하는 조건부 추격자의 습성은 순간 스냅샷이 아니라 시간에 걸친 행동열로만 식별된다.

**⚠️ 한정:** 이건 "동일 기체라 승리 불가능"이라는 무효한 대칭 논증이 **아니다.** 이기는 비대칭은 실재하고 도달 가능하다 — 다만 **상태·이력에 있고 순간 사진엔 없어서**, 무상태 f가 정의상 접근 못할 뿐이다. **이력을 읽는 상태 스위치만** 접근한다.

**실증 (게인 튜닝이 아니라 상태 스위치만 닫았다):**

| 상황 | 무상태 f 결과 | 상태 스위치 적용 후 |
|---|---|---|
| 조건부 도주 상대(D2_00) | 압박↔도주 평형 → 무 | 미끼-낚아채기 → 100:91 |
| 개전 헛다이브 상대 | 따라 내려가 저고도 엉킴 → 무 | 다이브 무시·고도 유지 → 100:96 |
| 덱 반격형(D2_05) | 정면 맞불 → 반격 우세 → 패 | 정면 최대G 자제 → 100:96 |
| 평행 정체(E1) | 접근율 0 → 현상 유지 → 무 | 정체 누적 감지→수직 강제 → 100:96 |
| **합** | 17/17 | **42/42 (무패·무승부 없음)** |

**결론:** 축 B는 튜닝 부족이 아니라 **표현력의 구조적 부재**다. 무상태 f는 대칭 교착을 어떤 게인으로도 못 깬다.

# Part C — 개선

## C.1 우선순위 로드맵

```
[1] 로컬 core2 DPS 25→50 동기화        ← 확정 규칙 반영, 유일한 채점 코드 변경.
[2] 확정 규칙에서 챔프/정책 재검증      ← 42/42가 새 게임에서 재현되나. 진짜 다음 작업.
[3] F3 리플레이 3종                     ← [2] 재검증 계측(per-tick)에 필요.
[4] F5/F6 수치 위생 + F4 배터리 확인    ← 묶어서.
──── 축 A는 규칙 확정으로 대부분 해소; 아래가 본 과제 ────
[5] 축 B: 무상태 L2 위에 상태 스위치 층 추가 (하이브리드)
```

## C.2 축 B 개선안 — 연속 제어를 유지한 하이브리드

**연속 L2를 대체하지 않는다.** 바닥에 두고(약 99% 운전), 무상태 f가 못 푸는 소수 교착 국면에서만 잠깐 켜지는 상태 스위치를 얹는다. 핵심은 **이 방식이 core2 기존 설계와 이미 정합**한다는 점이다.

**core2는 이미 이 선을 넘었다:**
- `mode="stable"`, `mode="control_zone"` — 특정 국면에서 연속 법칙을 이산 법칙으로 이미 교체 중 → 상태 스위치는 **같은 mode 어휘의 확장**.
- `Commit/Cooldown` 데코레이터 — 결정론 시계로 "한번 정하면 몇 초 유지"를 이미 구현 → 스위치도 동일 인프라.
- `BFMGuidance`의 **D6 원칙**("반사적 최대G 아님")은 이미 스위치의 정신("교범 처방이 역효과인 국면엔 다른 처방")과 같다. "덱 정면 최대G 자제" 스위치는 D6의 문자 그대로의 확장이다.

**4개 스위치 (각각 하나의 무/패를 닫음):**

| 스위치 | 상황 | 하는 일 | core2 매핑 |
|---|---|---|---|
| **미끼-낚아채기** | 조건부 도주 상대 | 위협 낮춰 꾀어내고, 덤빈 순간 뒤 낚아챔 | `mode="bait"`→접근율 부호반전 감지→`snap` |
| **헛다이브 무시** | 개전 애꿎은 급강하 상대 | 안 따라감, 고도 유지, 재상승 시 위에서 덮침 | "적 하강중" 조건→`mode="hold_perch"` |
| **정면 자제** | 덱 반격형과 정면 교차 | 최대G 참고 각도전 전환 | "덱+정면" 조건→`mode="suppress_headon"` |
| **교착 깨기** | 나란히 정체 | 정체 시간 세다 한계 넘으면 수직 강제 | 정체 누적기→`mode="break_stalemate"` |

**설계 제약 (강건성·감사성 보존):**
1. 각 스위치는 **명명된 물리 조건**으로 켜진다(주관적 시간 상수 금지 — loop17에서 "34초 전이면"을 "적이 하강 중이면"으로 탈시계화한 교훈).
2. 발동은 **audit에 기록**(core2 기록 철학과 정합).
3. **과적합 스위치 배제** — 조건을 넉넉히 흔들어도 성능 유지되는(load-bearing 검증) 것만.

## C.3 검증·반증 계획

축 B 주장은 반증 가능하다. **축 A 수정 후**(WEZ·틱레이트 정합, 양쪽 실제 제어 300s), core2 연속 L2 단독으로 D2_00·D2_05·E1을 겨룬다.
- 전부 승리 → 스위치 불필요, 축 B 반증(순수 L2가 정답이며 바람직).
- 무/패 발생 → 구조적 한계 실증, 하이브리드 필요.

예측은 후자(17-loop 일관 증거)이나 **실측이 유일한 판정자**다. 축 A 선행 없이는 시험 자체가 틀린 게임 위에서 도므로 무의미.

## C.4 결론

- **core2의 강점은 실재한다** — 연속 제어의 우아함, 총 조준·에너지 관리, 기록 가능성은 core-live보다 낫다. 폐기 대상 아님.
- **축 A는 규칙 확정으로 닫혔다** — F1·F2·F7은 core-live RULEBOOK을 정본 가정한 데서 온 오판이었고, 확정 룰북(엔진=core2)이 core2 채점을 정본으로 못박았다. 남은 건 로컬 DPS 25→50 동기화 + 우리쪽 계측 인프라뿐.
- **축 B(무상태 무승부)는 설계 확장으로 해결** — 연속 L2 유지 + 소수 교착 국면에 상태 스위치. core2 자신의 mode/Commit 패턴과 정합. 단 **42/42는 확정 규칙에서 재검증 후에만 유효**하다(초판은 다른 게임의 해였다).
- **Red Team 기준:** 무상태 조절기 단독은 실력 있는 상대에게 무승부하고, 무승부 대항군은 훈련 도구로서 존재 이유가 없다. **축 A로 채점을 바로잡고 축 B로 치명성을 확보**하는 것이 core2를 유효한 대항군으로 만드는 경로다.
