# ACMI 브라우저 뷰어

core2 매치 리플레이(`.acmi`)를 **Tacview 설치 없이** 브라우저에서 3D 재생하는 디브리핑 도구.
Python stdlib 서버 + three.js(vendored, MIT). 외부 의존성·빌드 없음.

## 실행

```bash
# repo 루트에서 (가상환경 불필요 — stdlib만 사용)
python tools/acmi_viewer/server.py                 # 서버 + 브라우저 자동 열기
python tools/acmi_viewer/server.py --no-open       # 서버만 (헤드리스·원격)
python tools/acmi_viewer/server.py --port 7901 --replays replays
```

기본으로 브라우저가 열린다(크롬 우선). **그 포트에 이미 서버가 떠 있으면** 새로
띄우지 않고 탭만 연다 — 그래서 두 번째 실행이 "주소 사용 중" 으로 죽지 않고, 보고
싶을 때 같은 명령을 다시 쳐도 된다.

### 지면 지도 굽기 (선택)

교전 좌표는 `engine/state.py:ned_to_lonlat` 이 **lon0=127.0 / lat0=37.0**(경기 남부 내륙)로
찍는다. 그 좌표 위의 실제 지도를 지면에 깔 수 있다:

```bash
python tools/acmi_viewer/make_map.py                       # Esri 위성, z12, 64km
python tools/acmi_viewer/make_map.py --source osm          # OSM 지도
python tools/acmi_viewer/make_map.py --zoom 13 --span-km 40  # 더 선명하게, 좁게
```

산출물 `static/maps/`(git 제외 — 타일 영상은 재배포하지 않는다). **없으면 종전의
무지 평면 + 격자로 자동 폴백**하므로 필수는 아니다. Pillow 필요(matplotlib 의존성이라
requirements 설치 시 이미 있다).

> **왜 평면인가** — 엔진 물리가 평지다(평면근사 투영, 하드덱은 해수면 1,000ft 고정).
> 실지형 고도를 넣으면 산을 통과해 나는 화면이 되어 승패 판정과 모순된다. 그래서
> 지도는 고도 0 평면에만 입히고, Cesium 같은 지구 엔진은 쓰지 않는다.
> Web Mercator 축척은 중심 위도 하나로 근사 — 64km·37°N 에서 가장자리 오차 ≈0.4%.

브라우저 URL 파라미터:

- `?replay=<파일명>.acmi` — 특정 리플레이 바로 열기 (하위 폴더는 `canon/xxx/yyy.acmi`)
- `&t=<초>` — 해당 시각으로 점프 (예: `?replay=xxx.acmi&t=40`)
- `&skin=team` — 기체를 팀색으로 재도장. 기본은 원본 F-16 도장이고, 그때 **팀 식별은
  항적선 색이 담당**한다(청/적 굵은 선). 기체까지 색으로 구분하고 싶을 때 쓴다
- `&me=blue|red` — 어느 쪽이 "우리 기체"인지 지정(1인칭 HUD 에 `★MINE`). 생략하면
  로스터 녹화 파일명 `vs_<상대>_<내진영>.acmi` 에서 읽고, 못 읽으면 표시하지 않는다
- `&aim=1` — 조준점 마커(와이어프레임 구 + 노즈 연결선) 표시. L1 pursuit·L2 aim 을
  눈으로 확인할 때만. 기본은 꺼져 있다(기체 앞에 늘 떠 있어 시야를 어지럽힌다)
- `&ground=map|grid|plain` — 지면. 상단 셀렉트로도 바꿀 수 있고 브라우저에 기억된다
- `&camera=blue|red|both|free`, `&dist=<m>` — 초기 카메라 모드·거리. 근접 화면
  (화염·베이퍼 확인, 복기 도판 캡처)을 바로 열 때 쓴다

키보드:
- **스페이스** = 재생/정지
- **← / →** = 시점 이동(1초). **Shift+←/→** = 5초. 재생 중이든 아니든 그 자리에서 민다.

배속은 **⏩ 빨리감기 / ⏪ 되감기** 버튼으로 조절한다(누를 때마다 0.25×→8× 한 단계씩).
반대 방향을 누르면 먼저 1× 로 돌아온 뒤 그 방향으로 간다 — 되감기는 배지에 `◂` 로
표시된다. (방향키는 배속이 아니라 **스크럽**에 배정했다 — 역할을 나눠 둘 다 쉽게 쓴다.)

## 소리 (합성)

상단 `🔇 소리` 버튼으로 켠다. **음원 파일을 쓰지 않고 Web Audio 로 합성**한다 —
라이선스 문제가 없고(이 저장소가 F-16 모델에서 겪은 것과 같은 문제), 스로틀·거리·
상대속도에 따라 매 프레임 파라미터를 밀 수 있어 녹음 크로스페이드보다 정확하다.
0.25~8배속·스크럽에도 재생 위치를 맞출 필요가 없다.

초판은 대역통과 잡음 하나 + 톱니 하나여서 바람소리처럼 들렸다. 실제 제트 소음은
성격이 다른 성분의 합이라 그렇게는 두께가 안 난다.

| 성분 | 근거 |
|---|---|
| **저역 럼블** | 제트 혼합 소음의 **몸통**. 하류의 큰 와류(제트 지름 규모)가 저주파를 낸다 |
| 중역 로어 | 같은 혼합 소음의 중간 대역 |
| 고역 히스 | 노즐 근처 작은 와류. 가까울 때만 들린다 |
| **버즈소** | 팬·압축기는 축 회전수 f₀ 의 **배음 다발**을 낸다(50~2400Hz 에 50~60Hz 간격 톤 계열). 톱니파가 정확히 그 구조라 공진 대역통과로 훑는다. **f₀ 가 스로틀을 따라 오르는 것이 "가속음"의 정체** |
| AB 럼블 + 스크리치 | 저주파 연소 불안정에 초음속 제트의 충격-연계 소음(좁은 공진). `throttle>0.5` 에서만 — 엔진 파일의 tsfc→atsfc 전환점과 같은 기준 |
| **대기 흡수** | 거리가 멀수록 고역이 먼저 죽는다. 보이스마다 거리 저역통과 — **이게 없으면 아무리 쌓아도 먼 제트가 코앞처럼 들린다** |
| 기총 | M61A1 은 분당 6,000발 = **초당 100발** — 개별 발사음이 아니라 100Hz 펄스열("BRRRT"). 낱발을 100개/초 예약하는 대신 100Hz 톱니 LFO 로 진폭을 깎아 연속 버스로 낸다 |

공간감은 **합성 임펄스 응답**(잡음 지수 감쇠)의 컨볼루션 잔향을 옅게 섞어 낸다 —
이것도 파일이 아니다.

거리는 1/r 감쇠 + 원거리 컷오프, 도플러는 카메라 기준 시선방향 상대속도로 건다
(교전 속도 200~300m/s vs 음속 340m/s 라 지나갈 때 음이 뚝 떨어진다). 잡음원은
선형합동 난수로 만들어 **같은 판이면 같은 소리**다(`Math.random` 미사용).
브라우저 자동재생 정책 때문에 버튼을 누른 시점에만 `AudioContext` 를 만든다.

## 디자인 원칙

- **어두운 계기 테마.** 예전에는 반투명 흰 카드였는데, 그러면 UI 가 화면에서 가장 밝은
  요소가 되어 기체·항적과 주목을 다툰다. 계측 도구는 영상이 주인공이고 UI 는 물러나
  있어야 한다. 어두운 크롬은 밝은 하늘과 어두운 바다 **양쪽**에서 일정하게 읽히기도
  한다(흰 패널은 밝은 하늘 위에서 대비가 무너졌다).
- **값은 모노, 라벨은 sans.** 숫자는 폭이 고정돼야 값이 흔들려도 자리가 안 움직인다.
  라벨은 대문자·자간을 줘 한 단계 뒤로 물린다 — 주인공은 값이다.
- **계기는 라벨을 달지 문장을 쓰지 않는다.** 조종간 범례에 있던 설명 문장
  ("간격 = FBW 가 깎은 양")은 패널 폭의 절반을 먹고 있었다. 그건 이 README 의 일이라
  옮기고, 캔버스에는 두 마커의 이름만 남겼다.
  (그 뜻: **주황 = 조종사 명령 / 회색 테두리 = 조종면 실위치. 둘의 간격이 FBW 가 깎은
  양이고, 가로축이 롤·세로축이 피치다.**)
- **팀 색은 띠로만.** 열 안의 카드·조종간·1인칭이 같은 좌측 띠를 공유해 좌=청 / 우=적
  대응이 화면 전체에서 안 끊긴다. 색을 넓은 면에 칠하면 기체의 팀 색과 경쟁한다.
- 간격은 4의 배수, 모서리는 6 하나, 컨트롤 높이는 28px 하나로 통일.

## 화면 구성

- **3D 씬** — F-16 실기 형상·원본 도장, **팀색 항적**(굵기가 화면상 일정한 카메라 지향
  리본 — WebGL 이 `linewidth` 를 무시해 1px 선밖에 못 그리므로 리본으로 낸다.
  **노즐 뒤 + 화염 뒤**에서 시작하고 — 무게중심에서 그리면 리본이 기체와 화염을
  덮는다 — 최근 12초가 진하고 굵으며 이력은 옅게 남는다. 속도감은 두 장치로 낸다:
  페이드가 **시간 고정**이라 빠를수록 밝은 꼬리가 길고, **1초 간격 밝기 띠**가 있어
  한 칸이 정확히 1초다. 즉 속도가 인상이 아니라 눈금으로 읽힌다),
  Gun WEZ 원뿔, **기총 예광**(사격 중 기수 앞 1,000m — `acmi.py` 의 Beam 과 같은 조건·기하),
  LOS(InWEZ 시 적색)·속도 벡터(팀색)·리프트 벡터(gmode 색), 하늘 그라데이션과 원경 haze
  — tacview ai-combat-analysis addon 정합. 조준점 마커는 `?aim=1` 일 때만
- **하늘** — three.js 공식 `Sky`(Preetham 대기 산란). **레일리 산란**(하늘이 파란 이유)과
  **미 산란**(태양 주변 후광)을 각각 계산하므로, 천정↔지평이 비선형으로 이어지고 태양
  방향에 밝은 후광이 생겨 방위감이 난다. 예전 2색 선형 그라데이션은 고도가 오르내려도
  늘 같은 하늘이라 배경 판때기로 보였다. 값은 맑은 낮 고고도(turbidity 2, rayleigh 2,
  mie 0.005/0.8), 태양은 남서 25° 고도 — **방향광이 하늘의 태양과 같은 방향**이라
  기체 음영으로 자세가 읽힌다(어긋나면 밝은 면과 그림자가 따로 놀아 입체감이 거짓이 된다)
- **지면 4종** — `바다`(기본) / `지도`(위성, 실제 좌표) / `격자`(계측용) / `없음`.
  **왜 바다인가**: 엔진 물리가 평지이고 하드덱이 **해수면** 1,000ft 고정이라, 평평해야
  하는 지면 중 실사가 되는 것이 바다이고 의미도 맞는다. three.js 공식
  `Water`(webgl_shaders_ocean)는 반사 카메라로 한 번 더 렌더하는데, 이 뷰어는 본 화면
  + 1인칭 2개를 한 프레임에 그려서 반사 패스가 **프레임당 3번** 붙는다. 게다가 교전
  고도 12,000~25,000ft 에서는 수면에 비친 기체가 보이지 않고 눈에 들어오는 것은
  ①프레넬(시야각에 따른 색 변화) ②태양 반짝임 길 ③잔물결 질감뿐이라, 그 셋만 셰이더로
  직접 낸다(추가 패스 0). 잔물결 진폭은 거리로 죽인다 — 멀리서 픽셀보다 잔 물결을
  그리면 지글거림만 는다. 파도도 **경기 시계**로만 흐른다.
- **지면(구)** — `지도`(위성, 실제 좌표) / `격자`(계측용) / `없음`. 격자는 1,000ft
  가는 선 · 5,000ft 굵은 선이고, 프래그먼트에서 그려 **화면상 굵기가 줌과 무관하게
  일정**하다(GridHelper 로 깔면 원경에서 모아레가 생긴다). 위성 영상은 고주파 무늬라
  항적·기체와 주목을 다투므로, 기하를 집중해서 볼 때는 격자가 낫다
- **엔진·기상 표현** (전부 기록된 값에서만 유도 — 난수·벽시계 없음):
  - **AB 화염** — `Throttle > 0.5` 에서만, 길이·밝기가 `(thr−0.5)/0.5` 에 비례.
    형상은 원기둥 껍질 하나이고 **모양·색·밝기는 전부 프래그먼트 셰이더가** 만든다
    (예전의 단색 원뿔 2겹은 색이 평평해 스티커처럼 보였다):
    · **부착점·치수는 모델 정점에서 실측**했다 — 배기 출구는 기체 뒤 끝(−0.5)이
      아니라 −0.4687 이고(뒤 끝은 수평미익이다) 슈라우드 반지름은 전장비 0.0705.
      −0.5 에 붙이면 플룸이 기체에서 떠 보인다
    · **단면 프로필** — 노즐 직후 살짝 부풀었다가 **뾰족하게 수렴**한다. 뒤로 갈수록
      벌어지는 원뿔로 그리면 배기가 아니라 통을 매단 것처럼 보인다
    · **길이** — F-16(PW-229)의 가시 플룸은 25~30ft, 전장이 49.4ft 이므로 전장의
      0.5~0.6. full AB 에서 0.55 (`FLAME_LEN_BASE` + `FLAME_LEN_AB`)
    · **충격 다이아몬드(Mach disk)** — 과팽창 제트가 팽창·압축을 반복하며 축을 따라
      밝은 마디가 규칙적으로 선다. 간격이 하류로 벌어지고(`pow(x,0.75)`) 대기압에
      가까워지며 사라진다(`exp` 감쇠). 밝은 마디만 더하면 균일한 주황 덩어리가 되므로
      **어두운 마디도 함께 판다** — 그래야 마디가 마디로 보인다
    · **부피감** — 껍질 하나로 부피를 흉내내는 정석. 시선이 껍질 정면을 뚫으면 가스를
      길게 지나가고(짙고 뜨겁다), 실루엣을 스치면 짧게 지난다(옅다). `|n·v|` 하나가
      알파와 심(core) 온도를 동시에 준다
    · **색 스펙트럼** — 관측 기준으로 노즐 직후가 **창백한 청색**(3,200°F 급, 완전
      연소)이고 하류로 갈수록 노랑→주황(저온·불완전연소), 끝은 흐릿하게 사라진다.
      축 온도를 지수 감쇠시켜 그 순서가 나오게 했다
    · **난류** — 값 노이즈 fbm 4옥타브가 배기와 함께 뒤로 흐른다. 텍스처를 안 쓰므로
      외부 자산이 필요 없다
    · 시간은 **경기 시계**로만 흐른다 — 벽시계·난수를 쓰면 같은 판이 매번 달라져
      이 저장소의 결정론 규약을 깬다(피격 비네트와 같은 원칙)
    · 글로우는 후처리 블룸(UnrealBloomPass)이 정석이지만, 이 뷰어는 본 화면과 1인칭
      2개를 **scissor 뷰포트로 나눠** 한 프레임에 그린다. EffectComposer 는 전체화면
      쿼드로 도는 구조라 뷰포트마다 컴포저(렌더타깃 3벌)를 두어야 해 비용이 크다.
      그래서 글로우는 노즐 빌보드 한 장으로 재질 안에서 낸다 — 모든 뷰포트에서
      똑같이 동작하고 추가 패스가 없다
    근거: 엔진은 F100-PW-229(`augmented=1`, `augmethod=2`, mil 17,800 / max 29,000 lbf).
    JSBSim 에 throttle 을 직접 넣어 재면 15,000ft·350kt 정상상태에서
    `0.50 → 14,842 lbf · 10,349 pph · TSFC 0.70`(건추력),
    `0.60 → 21,474 lbf · 44,022 pph · TSFC 2.05`(AB) — 엔진 파일의
    `tsfc 0.74 → atsfc 2.05` 로 **0.5 에서** 갈아탄다. 굵기는 노즐 실치수
    (출구 지름 ≈1.25m / 전장 15m) 기준
  - **구름 2층** — 교전 고도가 12,000~25,000ft 라, 그 **아래** 적운 갑판(6,000ft)과
    **위** 권운(32,000ft)을 두면 교전을 안 가리면서 고도감·속도감이 난다. 볼류메트릭
    레이마칭은 1인칭 포함 프레임당 3번 돌아 너무 비싸므로 층마다 평면 한 장 + fbm
    노이즈 알파로 낸다. 피복 문턱 아래는 구멍이 뚫려 갑판이 끊겨 보이고, 시선이
    스칠수록 짙어진다(광학 두께). 흐름도 **경기 시계**로만.
  - **고G 베이퍼** — 익단 와류 응결. `Nz`(실측 하중배수) 4G 부터 보이고 7.5G 에서 최대,
    `AOA` 가 크면 짙어진다. **콘트레일은 일부러 넣지 않았다** — 배기 응결은 대략
    −40°C 이하(보통 26,000ft 이상)에서 지속하는데 이 교전은 12,000~25,000ft 다.
    천음속 충격 원뿔도 없다(여기 속도는 마하 0.5~0.85). 습도는 시뮬레이션에 없으므로
    "습한 날" 을 가정한 표현이다
- **화면 배치** — 진영마다 **세로 열 하나**(좌=청 / 우=적)이고 그 안에서
  [수치 카드] → [조종간] → [1인칭 콕핏] 순이다. 예전에는 여섯 패널이 각자 화면
  모서리에 절대배치돼 있어 창이 짧아지면(울트라와이드) 서로를 덮었다. 이제 자리가
  모자라면 카드만 줄고 아래 둘은 크기를 지킨다. 스텝 수는 상단 시계 옆으로 옮겼다
  (거리·ATA·AA·HCA 를 화면 한복판에 또 띄우던 초록 패널은 카드와 같은 숫자라 없앴다).
- **addon 정합 패널** — 카드 내 L1~L4 블록(node/pursuit/maxG·G명령/가용·dphi·aim±·thr·kts/ft/G/°T·에너지 ⬆️⬇️·UNDER ATTACK)
  (반각 30°·3,000ft, `units.py`/RULEBOOK §4 과 동일 — 강조 판정은 ACMI `InWEZ` 플래그 그대로.
  원뿔은 **기수(자세) 정렬**: 룰의 ATA 가 BEM 종축(boresight) 기준이므로(D7, 2026-07-17)),
  고도 인지선, 격추 시 회색 전환.
- **기체 카드** — Health 바, CAS/HDG/거리[ft]/접근율[kts]/ATA/AA/HCA/RollOff/스로틀/G명령/G가용,
  L1~L3 결정 문자열 (`docs/ACMI_MESSAGES.md` 참조).
- **타임라인** — 위에 **사격 구간 띠**(위=청 / 아래=적), 아래에 사건 틱.
  · 띠: `InWEZ` 구간을 그대로 칠한다. 진하기는 조준 등급 — 룰북 데미지가 ATA 계단
    (2°/10°/20°/30° → 50/37.5/25/12.5 HP/s)이라 같은 WEZ 라도 정조준이면 훨씬 아프고,
    그 차이가 농도로 읽힌다. 점(북마크)만으로는 **얼마나 오래 물렸는지**를 알 수 없어
    빠르게 스크럽할 때 사격 구간을 못 집었다.
  · 틱은 세 종류를 색·높이로 가른다: **피격(주황·큼) / 승패(적·가장 큼) / 전술 전환
    (회색·작음)**. 전부 같은 색이면 30여 개가 고르게 늘어서 피격이 묻힌다.
    같은 종류끼리 1.5초 안쪽은 하나로 뭉치고 툴팁에 `(외 N)` 로 적는다.
  · 호버=내용, 클릭=점프, 스크럽, 재생/배속(0.25–8×).
- **카메라** — 양측 중점 추적(기본) / Blue·Red 추적 / 자유. 마우스 드래그·휠 오빗.
- **1인칭 뷰 + F-16 HUD(좌·우 하단)** — 청/적 각각의 콕핏 시점. 상단 `1인칭` 버튼으로 토글.
  - 시선 = 기수(boresight). **ATA 가 기수 기준**이라 화면 정중앙 = ATA 0 이고,
    조준 상태가 이 화면에서 바로 읽힌다. FOV 65° 로 사격창 ±30° 가 세로에 다 들어온다.
  - **심볼로지**: 피치 사다리(10° 간격, 오름=실선/내림=파선), FPM(비행경로 마커 —
    건 크로스와의 차이가 AOA), 건 크로스 + 2° 피퍼(최대 피해 원뿔), TD 박스(적기 +
    거리, 화면 밖이면 방향 화살표), 속도·고도 테이프, 방위 테이프, AOA/G/Vc/L1 노드.
  - 각도 심볼(사다리·FPM·TD)은 눈대중이 아니라 **PIP 카메라로 실제 투영**한다 —
    FOV 를 바꿔도 3D 장면과 어긋나지 않는다(`tests/test_map_geo.mjs` 가 못 박는다).
  - **피격 비네트** — HP 가 실제로 깎이는 동안 화면 가장자리가 붉게 맥동한다. 세기는
    피해율(최대 50HP/s) 비례, 위상은 **경기 시계**로만 만든다(난수·벽시계 금지 →
    같은 판은 항상 같은 화면).
  - 롤이 그대로 실려 **배면비행이 화면에서도 뒤집힌다**.
  - 어느 쪽이 우리 기체인지 헤더에 `BLUE/RED + 호출부호 + ★MINE` 로 못 박는다 —
    로스터는 상대마다 양 진영을 다 돌려서 우리 기체가 판마다 진영을 바꾼다.
  - 본 화면과 같은 씬을 scissor 뷰포트로 나눠 그린다(지오메트리·텍스처 업로드 한 벌).
    자기 기체·WEZ 원뿔·벡터·예광과 **상대의 조준점 마커**는 그 뷰에서만 숨긴다.
- **조종간 패널** — 스틱 상자(가로 롤 / 세로 피치, 주황=조종사 명령, 회색 테두리 사각
  =조종면 실위치, **둘의 간격이 서보 지연·포화**), 스로틀(0.5 이상 AB 구간 + %),
  러더(노랑=명령, 빨강=실위치). 두 마커의 뜻은 패널 안 범례에 상시 표시한다 —
  정사각형이던 시절엔 이름을 붙일 자리가 없어 "빈 사각형이 뭐냐" 가 됐다.
- **지면** — `static/maps/` 가 있으면 실제 좌표 위의 지도 + 0.1° 위경도 그래티큘,
  없으면 무지 평면 + 격자.

## 검증

```bash
node tools/acmi_viewer/tests/test_acmi_parse.mjs   # replays/ 전체 파싱 + 앵커 매치 대조
node tools/acmi_viewer/tests/test_map_geo.mjs      # 지도 배치·1인칭 카메라·조준 링 정합
```

`test_map_geo.mjs` 가 잡는 것: 지도 중심의 동서·남북 투영이 `acmi.js` 트랙 투영과 같은
식인지, 축척이 m/px 과 맞는지, 표본 녹화 전 구간이 지도 안에 드는지, 1인칭 카메라의
시선이 기수와·화면 상방이 기체 상방과 일치하는지(5자세), SVG 조준 링 반경이 FOV 와
맞는지. 헤드리스 크롬은 이 뷰어를 렌더하지 못하므로(WebGL+glTF 적재가 끝나지 않음)
눈으로 못 보는 부분을 수학으로 대신 못 박아 둔 것이다.

파서는 core2 `acmi.py` 출력 전용(범용 Tacview 호환 아님). 단위: `Distance`[ft],
`CAS`[m/s — ACMI 스펙, 표시 시 kts 변환], `ClosureRate`[kts], `T=` 고도[m].

## ai-combat-web 이식 노트

`static/` 의 JS 모듈은 프레임워크 무관이라 Next.js 로 거의 그대로 옮겨진다:

1. `acmi.js`·`scene.js`·`hud.js` 를 웹 저장소로 복사, three.js 는 `npm install three` 로 대체
   (import map 대신 번들러 해석; `vendor/OrbitControls.js` → `three/addons/controls/OrbitControls.js`).
2. `'use client'` 컴포넌트가 컨테이너 div 를 만들고 `ReplayScene` 을 마운트.
3. 데이터 소스는 `main.js` 의 `loadReplay(url)` 패턴 그대로 — Supabase `matches.replay_url` 을
   fetch (11MB급이므로 storage gzip 전송 권장). index.html 의 HUD 마크업/CSS 는 컴포넌트 JSX 로 이관.

## 기체 모델 처리 방식

`static/f16.js` 가 glTF를 한 번만 읽어 뷰어 규약으로 정규화한다.

- **축 정합** — 모델 로컬축(기수 +X·상방 +Y·우익 +Z)을 뷰어 규약(기수 +Y·상방 +Z·우익 +X)으로
  순환 치환. 행렬식 +1이라 거울 반전이 아니다(반전되면 롤 방향이 뒤집혀 보인다).
- **축척** — 전장을 1로 정규화하고 중심을 원점에. 절차적 폴백과 같은 규약이라 두 경로가
  같은 크기로 그려진다. (원본 1 unit ≈ 0.1 m: 전장 15.1 m·익폭 9.4 m로 실기와 일치)
- **부품 취사** — 원본(Sketchfab) 부품 이름이 실제 부위와 어긋나 있어(`instrGlass` = 항법등
  유리) 점군을 측면·평면으로 찍어 눈으로 확인했다. 전개된 착륙장치·착륙등·HUD·항법등은 숨기고
  동체·캐노피·조종석·익단 레일·접힌 착륙장치 도어만 그린다.
- **팀색 투톤** — 절차적 형상은 평면의 앞/뒷면으로 상·하면을 갈랐지만 실기는 닫힌 입체라
  그 수법이 통하지 않는다. 대신 기체 로컬 법선의 z 성분으로 섞어(`onBeforeCompile`) 동체
  아랫면이 밝은 팀톤이 되게 한다 — 배면비행 식별 단서가 그대로 유지된다.
  아래쪽 보조광을 함께 둔다(없으면 하면이 그늘로 떨어져 격추 회색처럼 읽힌다).
